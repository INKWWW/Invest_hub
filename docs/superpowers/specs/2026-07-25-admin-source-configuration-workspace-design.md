# 管理员信息来源配置工作台与 X 博主安全移除设计

## 文档状态

- 阶段：V2 后的管理员可用性改进
- 状态：**已批准；本地实现完成，远程迁移与部署待单独授权**
- 日期：2026-07-25
- 设计对象：`/admin/sources`

## 1. 背景与问题

当前来源页将 Discord 与 X 的创建、配置、覆盖、Worker、规则、作者管理和运行操作放入同一张八列表格。每个来源本质上是一组有状态的管理工作流，而不是一行静态记录；在窄列中嵌入完整表单会导致标签、输入和按钮被压成竖排，管理员也无法快速判断某个来源下一步该做什么。

本设计服务于管理员。页面的单一任务是：管理员能够按来源类型快速判断来源是否可用，并在不混淆 Discord/X 边界、不泄露普通读者不可见信息的前提下完成正确的配置或运行操作。

## 2. 设计决定

### 2.1 来源类型分区

`/admin/sources` 顶部提供同级、可访问的来源分区：

```text
信息来源                         [+ 新建来源]

[ Discord 配置 · n ] [ X 配置 · n ]
```

1. `Discord 配置` 与 `X 配置` 是页面内的独立配置工作区，而不是同一张表内的筛选列；当前工作区具有明确活动状态并可由键盘操作。
2. 默认打开最近一次选择的分区；在无历史选择时打开 Discord。URL 可表达当前分区，刷新或分享管理员链接后不丢失上下文。
3. 每个分区只渲染其对应类型的创建入口、来源档案卡和类型适用的管理模块；不显示另一类型无关的字段、空单元格或操作。
4. 此设计不建立 Discord/X 的混合采集、共享 checkpoint、共享摘要或共享读者数据投影。

### 2.2 来源档案卡

来源列表由来源档案卡替代全宽编辑表格。卡片只展示可决定下一步操作的安全信息：展示名称、来源类型、启停状态、身份或覆盖状态、授权 Worker 的安全显示值和最近完成时间。内部 ID、浏览器 URL、Cookie、Profile 引用、原始正文、Prompt 或 Provider 诊断不进入页面。

```text
┌ AllInvestHK · X ─── 已启用 ─── 身份待验证 ─────────────── [管理]
│ Worker：v2-x-worker        覆盖：未初始化        最近完成：—
│
│ 配置 ── 身份验证 ── 初始化覆盖 ── 更新与回填
│   ✓           ● 当前步骤            ○                ○
└────────────────────────────────────────────────────────────────────
```

上述轨道仅表达来源真实的操作顺序：来源资料已保存、身份是否解析、连续覆盖是否初始化、之后是否可以更新/回填。它不是采集进度、成功率或 SLA 的替代。

点击“管理”后打开该来源的详情工作区。详情以标签或分段承载：

- Discord：`来源资料`、`采集范围`、`作者配置`、`规则`；
- X：`博主资料`、`采集范围`、`更新与回填`、`危险操作`。

每次只展开一个来源的表单；保存后的成功、校验失败、可重试失败和进行中状态必须保留明确文本，不能被写成“无新增”。

### 2.3 X 博主移除

X 来源提供“移除博主”能力，但“从管理列表移走”与“删除持久化事实”严格区分。

1. 只有不存在任何任务、覆盖记录、原始/Canonical 帖子、分析、每日观点段或其他关联事实的 X 来源，才允许执行不可恢复的物理删除。确认框要求输入该博主的显示名或账号名；确认文案明确说明删除的是空来源配置。
2. 一旦来源已有任何任务或已持久化事实，物理删除不可用。管理员仍可选择“停止并归档”：停用来源及其 X 配置，使其不再被领取、更新或显示于默认活动列表；既有事实、摘要、任务、覆盖边界和证据关系按既有保留策略保留。
3. 存在 queued、leased、running 或 retryable_failed 的 X 任务时，不允许直接归档或物理删除。界面说明阻塞原因，并要求先按已批准的任务恢复/取消流程完成安全收口；本设计不新增绕过 lease 或删除运行证据的路径。
4. 危险操作不放在卡片主操作区、不以红色作为唯一提示。它位于 X 详情底部，先说明影响，再要求二次确认；成功提示与按钮用词保持一致。
5. 归档来源默认不显示在活动卡片中，但管理员可通过“已归档”筛选查看其安全元信息和归档原因；普通 Reader、Worker 与公开 API 不暴露归档操作或内部原因。

### 2.4 视觉与交互语言

页面使用现有 Invest Hub 的纸面阅读感，而非通用数据大屏：

- 颜色：`#F5F7F4` 雾面工作底、`#FFFDF8` 工作纸面、`#17252D` 墨黑文本、`#235A66` 深青主操作、`#B46C22` 需要注意的操作状态、`#A4473C` 危险操作；
- 字体：Georgia 仅用于页面标题和来源名称；系统无衬线用于说明；`ui-monospace` 仅用于时间、版本和经过截断/安全投影的技术标识；
- 卡片使用横向信息带与有限的边框/留白，不在每个字段外再套一个视觉容器；
- 桌面布局优先呈现来源状态与下一步，375px 下卡片改为单列、详情标签横向可滚动但不产生页面横向溢出；
- 所有标签、状态、按钮和确认框具有可访问名称、可见焦点和键盘顺序；减少动态效果，尊重 `prefers-reduced-motion`。

## 3. 范围与非目标

本设计只覆盖管理员来源管理体验和 X 博主安全移除能力。

不属于本设计：

- 改变 Discord 或 X 的采集协议、任务范围、checkpoint、恢复语义或 Reader DTO；
- 解析媒体、外部正文，或重新启用个人 Discord 账号采集；
- 删除已有保留期内的原始事实、摘要、证据、任务或 checkpoint；
- 建立 Discord/X 统一时间线、跨来源结论或普通用户配置能力；
- 在本 Spec 审阅与独立 implementation plan 批准前修改应用代码、数据库、RLS、API、Worker、部署或真实来源状态。

## 4. 验收标准

1. 管理员可在 Discord 配置与 X 配置间切换，且两者分别只显示适用的来源、创建入口和操作模块。
2. 1280px 下不存在将来源表单挤入窄列的表格布局；375px 下无横向页面溢出，卡片、切换、详情和确认框均可操作。
3. 一眼可见每个活动来源的展示名称、类型、启停状态、下一步、覆盖/身份状态及安全 Worker 信息；完整 UUID、内部引用和受保护内容不出现在页面。
4. X 空来源可在明确确认后物理删除；任一有事实或任务的 X 来源只能停止并归档，且历史事实仍可按既有权限和保留策略读取。
5. 对进行中或待恢复 X 任务，危险操作有明确阻断信息，不绕过 lease、取消证据或推进 coverage。
6. 管理员操作继续受现有角色边界保护；普通用户不能访问来源配置、移除/归档、任务状态或内部诊断。
7. 实施后必须覆盖分区切换、卡片/详情状态、X 空来源删除、带事实来源归档、运行中任务阻断、权限、响应式、键盘和无横向溢出测试；并通过现有控制面回归、lint、production build、脱敏检查与 `git diff --check`。

## 5. 实施门禁

本 Spec 仅记录产品与安全边界。用户审阅并明确批准后，才可编写独立 implementation plan；Plan 必须明确数据库约束、API/Worker 协作、归档和任务收口的事务顺序、回滚、迁移、测试与部署授权。该批准不等同于实施、远程 migration、部署或真实来源变更授权。
