# X 阅读页全量筛选与管理员入口设计

## 文档状态

- 阶段：V2 后的阅读可用性改进
- 状态：用户已直接提出并授权实施
- 日期：2026-07-26
- 设计对象：`/x` 阅读页及共享账户会话控件

## 1. 问题与目标

当前 X 阅读页默认锁定首个博主和首个日期，管理员虽有后台权限，但无法从阅读页直接进入配置管理。这使得需要横向浏览内容或维护来源时，操作路径不清晰。

本改动的目标是让 X 阅读页默认呈现全部可读的“博主 × 日期”日卡片，允许按博主、日期或两者共同筛选，并只在管理员会话中提供前往配置管理的入口。

## 2. 交互决定

### 2.1 管理员入口

共享会话区域在管理员的“退出 / 切换账号”旁增加“配置管理”链接，目标为 `/admin`。普通用户不渲染该链接；链接不会提升权限，`/admin` 既有服务端角色校验继续生效。

### 2.2 全部筛选

博主和日期下拉框均增加“全部”选项，并作为默认值。筛选组合的语义固定为：

- 全部博主 + 全部日期：显示全部日卡片；
- 指定博主 + 全部日期：显示该博主的全部日期；
- 全部博主 + 指定日期：显示该日期下的全部博主；
- 指定博主 + 指定日期：显示唯一匹配卡片。

筛选状态写入浏览器地址栏查询参数以支持刷新和分享：未筛选时不写参数；指定博主使用 `source`，指定日期使用 `date`。`all` 不是后端筛选值，API 接收到它时按未筛选处理。

### 2.3 内容边界与层级

每一张结果卡始终仅代表一个博主和一个自然日，并保留作者、日期、状态、观点和折叠证据。页面不会把多个博主或多个日期的观点合并、重新总结或暗示为统一结论。结果按日期倒序、同日按博主名称排序。

当筛选没有匹配项时，内容区显示明确的空状态，筛选控件仍可用。没有任何 X 日度内容时，维持现有“尚无可阅读的 X 信息”提示。

## 3. 数据、接口与安全边界

1. 不改数据库、采集、覆盖范围、checkpoint、任务或摘要生成逻辑；全量视图使用既有 `readXDay()` 安全投影。
2. 阅读页只展示既有 reader-safe DTO；不得在卡片、筛选或 URL 中加入原始内容、私有引用、Cookie、Profile、Worker、Prompt 或 Provider 信息。
3. `/api/reader/x` 保持可选 `source`、`date` 过滤；`source=all` 或 `date=all` 视为未指定，日期格式校验保持有效。

## 4. 验收标准

1. 管理员看到“配置管理”并可访问 `/admin`；普通用户不看到该入口。
2. `/x` 初始状态的博主和日期均为“全部”，并显示所有匹配日卡片。
3. 任一博主/日期组合只显示匹配的独立卡片，不合并跨博主或跨日期内容；无匹配时显示空状态。
4. 查询参数可恢复指定筛选，API 对 `all` 值按未筛选处理且继续拒绝非法日期。
5. 组件和路由测试覆盖角色入口、默认全量、组合筛选和安全呈现；通过全量前端测试、lint、生产构建、脱敏检查与 `git diff --check`。
