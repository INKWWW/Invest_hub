# X 判断对象范围与阅读展示设计

## 目标

修复 X 投资判断中“博主有明确操作表述、但原帖未明确对象”被错误展示为可执行对象的问题，并统一当日判断总结与单个博主观点的阅读表达。系统必须保留博主原有的操作表述，同时明确标记对象是否足以执行；不得补造标的、产业或资产范围。

阅读页采用已经确认的编辑式平铺方案：当日判断总结与单个博主观点是两个清晰的大模块，每个模块使用克制的浅色标题带区分；模块内部依靠留白、观点编号和细分割线组织内容，不使用层层嵌套的卡片或连续粗边框。单个博主区中的主题、观点、条件和不确定性与当日判断区使用同一套观点展示语法；每名博主的标题行加粗，便于连续阅读时识别博主边界。

## 已确认事实

2026-08-05 的生产判断中，原始可见内容确有“再次全仓投入”的操作表述，但未指出标的或资产。v3 单帖分析将 `action_intent` 记为 `build_position`，并把“当前帖未明确指明的标的或资产”写入 `action_scope`；v3 单博主窗口和跨博主当日判断均原样沿用，Reader 因此呈现“博主倾向：建仓（当前帖未明确指明的标的或资产）”。这不是对具体标的的虚构，却错误复用了 `action_scope` 的语义：该字段应只承载实际对象，不应承载“对象缺失”的说明。

现有 v3 Prompt、Worker Protocol、控制面完成接口和数据库校验共同要求“非 `none` 的 action intent 必须有非空 `action_scope`”。这个二态合同无法表达“有明确操作表述、对象未明确”的第三种状态，导致模型只能以占位说明满足结构校验。

## 范围

### 1. 操作对象合同

新的单帖、单博主窗口和跨博主判断合同增加必填字段 `action_scope_status`，其取值和字段一致性如下：

| `action_intent` | `action_scope_status` | `action_scope` |
|---|---|---|
| `none` | `not_applicable` | 空字符串 |
| 非 `none`，博主明确对象 | `specified` | 非空，且只包含原帖明确的标的、资产、产业、市场或策略范围 |
| 非 `none`，博主未明确对象 | `unspecified` | 空字符串 |

`unspecified` 仅表示博主明确说过某种操作，但没有说明操作对象；它不等同于 `none`，也不构成投资建议。Prompt 必须明确要求：对象不明时保留已明确的操作表述、填空 `action_scope`、将对象缺失写入 `uncertainties`，绝不能把“未说明对象”等解释文字写进 `action_scope`。

该结构变更采用新的版本化 Prompt/schema 合同，而不是伪装为旧 v3 输出：单帖为 `v4-x-post-analysis` / `v4-x-post-analysis-1`，单博主窗口为 `v4-x-window` / `v4-x-window-1`，跨博主当日判断为 `v4-x-cross-blogger` / `v4-x-cross-blogger-1`。Worker Runtime、Protocol、控制面完成接口、数据库 validator、Reader DTO 和结构化测试必须同时识别新合同；已持久化 v2/v3 记录继续可读，不重写、不伪造为新版本。

### 2. 已存 v3 记录的安全呈现

既有判断版本不可变，也不为修复展示问题直接更新 JSON。Reader 仅在已存 `action_scope` 明确是“对象未指明”的占位说明，或其同一条 `uncertainties` 明确记录对象范围缺失时，派生展示状态 `unspecified`：显示“操作表述：建仓”“对象：未明确，不可据此执行”，不回显占位说明为对象。没有足够依据判定为对象缺失的历史条目，保持原有经校验的展示，不能猜测或篡改其范围。

新合同生成的记录不依赖这种兼容判断，直接按 `action_scope_status` 展示。

### 3. Reader 文字与层级

当日判断和单个博主窗口中的每一条内容均使用以下顺序：主题标题、`观点 01/02/...`、直接陈述的观点正文、条件/来源/不同观点/不确定性。新的 Prompt 要求 `statement` 直接陈述内容，不以“博主认为”“一位博主表示”等生硬归因短语开头；归因由页面的来源字段承担。对已存记录，Reader 只可移除完全匹配的纯归因前缀，且不得改写观点、条件、确定性或标的文本。

当日判断总结和单个博主观点各自使用全宽、浅色、中文为主的模块标题带，标题带之外不再套叠大卡片。博主区按博主分块、最新完成窗口优先；博主标题行中的“博主”和显示名都使用更高字重。博主窗口内的主题和观点复用当日判断的排版，而非使用独立样式。既有日期和博主筛选交互、判断窗口顺序、证据追溯、覆盖说明与普通用户权限不改变。

## 非范围

本次不改变 X 采集、身份解析、任务调度、coverage、checkpoint、来源权限、原始内容保留期或 Provider 选择；不重新采集、不调用 Provider 回刷历史窗口，也不直接修改 `x_daily_judgement_versions`、单帖分析或窗口摘要。历史 v2/v3 内容不会被批量重生成为新版本。

本次也不改变系统“不提供交易建议”的边界。页面记录的是可追溯的博主操作表述；`unspecified` 状态必须比有明确对象的倾向更醒目地说明不可执行，而不能被视觉弱化为正常标的建议。

## 安全与兼容性

- Prompt 继续将博主正文、引用内容和分析文本视为不可信数据；禁止外部知识、提示注入和模型自行生成交易建议。
- `action_scope_status`、`action_intent`、对象范围、条件、不确定性、来源、analysis 和帖子证据须在所有边界执行精确字段、枚举与同源关系校验；任何不一致结果在持久化前拒绝。
- Reader-safe DTO 不得暴露内部 source、analysis、post 或运行时 ID，不得暴露原始文本、Prompt、Cookie、Profile、密钥或本地路径。
- Prompt/schema 升级必须保留旧记录的只读兼容分支；新版本不可从旧输入结构或旧 Prompt 伪造生成。

## 验收标准

1. 合成输入中有“买入/建仓”等明确操作表述但未给对象时，单帖、单博主窗口和跨博主输出均为非 `none`、`action_scope_status = unspecified`、空 `action_scope`，并带对象缺失的不确定性；任一层把说明文本写入 `action_scope` 必须失败。
2. 合成输入中有明确对象的操作表述保留该对象并标记 `specified`；没有操作表述时严格输出 `none/not_applicable/空范围`。不允许模型从价格、情绪或走势推断行动倾向。
3. Worker Runtime、Protocol、控制面 endpoint、数据库 validator 和 Reader 对新版本字段集合、枚举、ID 归属和版本号一致；非法状态组合、缺字段、额外字段、非法自然语言 ID 或不安全 telemetry 均在网络或持久化边界前失败。
4. 现有 v2/v3 记录可读且不被改写；明确的历史“对象未指明”占位记录显示“对象：未明确，不可据此执行”。
5. 当日判断与单博主区使用两个可辨识的模块标题带；无多层卡片嵌套；同一类观点在两个区域具有相同的“主题 → 观点编号 → 正文 → 元信息”结构；博主标题行视觉上强于正文。
6. 在桌面和 375px 宽度下，模块标题、博主标题、长观点、来源和不确定性均无横向溢出，键盘和屏幕阅读器语义保持正确。
7. 新增公开合成 fixture 与单元/跨边界回归通过；数据库、Worker、控制面测试、lint、production build、`git diff --check` 和 `bash scripts/v0/redact-check.sh` 通过后，才允许部署。部署后以已登录普通用户只读验收稳定 `/x`，核对新记录、历史兼容记录、博主/日期筛选及桌面/375px 展示。
