## 1. 问题本质与 V2 目标

个人投资研究需要的是对指定信息源的连续、可追溯理解，而不是把 X 的混合时间线重新搬到另一个网页。用户进入 V2 阅读页时，应能回答四个问题：

1. 这位指定博主在这个上海自然日实际发布了什么；
2. 其中哪些是该博主自己的观点、态度或操作倾向，哪些只是引用、回复或无评论转发；
3. 当前最新中文摘要有哪些证据边界、未解析媒体或不确定性；
4. 对应原帖在哪里可以在 X 中打开。

V2 的目标是在用户本人已登录、正常可见的 X 网页访问边界内，建立每位管理员配置博主独立的采集、恢复、每日中文摘要和按日期阅读闭环。它继承 V1/V1.1 已验证的事实优先、来源隔离、成功后推进 checkpoint、版本可追溯和安全读者投影原则；但不把 Discord 的 Adapter、分页行为或已部署运行方式视为 X 的既有验证结果。

## 2. 范围与非目标

### 2.1 本 Spec 的范围

V2 仅包含以下能力：

- 管理员配置、启停和查看指定 X 博主；每位博主是一个独立的逻辑采集对象；
- 每位博主独立的 checkpoint、任务、失败分类、局部重试、离线补采和有界历史补采；
- 在已登录且正常可见的 X 网页中，识别并持久化原创、引用、回复和无附加评论的普通转发；
- 对每条可持久化帖子保留可追溯的帖子身份、作者、发布时间、帖子类型、原始链接、附件/外链元数据及必要上下文关系；
- 每位博主、每个 Asia/Shanghai 自然日的中文摘要版本，及其与已确认 Canonical 帖子的证据关系；
- 面向管理员和普通用户的 X 阅读体验：按自然日和博主阅读当前摘要、折叠的原帖入口及折叠的历史摘要版本；
- 管理员专属的博主配置、手动更新、有界历史补采、任务状态、脱敏失败分类和局部重试；
- 公开人工 fixture、确定性测试、经用户明确授权的真实验收和脱敏工程证据。

### 2.2 明确非目标

V2 不包含：

- Discord/X 统一时间线、跨博主统一结论、跨博主综合摘要、跨来源主题聚合或共享视觉重构；这些属于 V3 或后续独立范围；
- 图片、视频、PDF、音频、表格、OCR 或外部文章正文解析。媒体和外链仅保留元数据、链接卡片与未解析提示；
- 用户独立博主列表、独立数据空间、阅读进度、已读未读或未读数量；所有已生成的阅读数据继续共享；
- 自动 Provider fallback、GLM API、第二个真实 Provider，或将 Codex CLI 表述为最终生产 Provider；
- 直接 X REST API、普通用户 Token 自动化，或在未通过独立验证前建设第二套完整浏览器采集框架；
- 改写现有 Discord 行为、V1/V1.1 共享协议、既有数据库契约、发布绑定或部署配置；
- 无人值守生产 SLA、全局数据清理任务、长期容量扩展和全系统运维能力。

## 3. 核心产品决策

### 3.1 博主是独立信息源，不是筛选条件

管理员配置的每位 X 博主都是一个独立信息源。其可见性必须来自用户本人已登录且拥有权限的网页会话；“当前页面可见”是访问边界，不是只采集屏幕上恰好出现帖子的筛选规则。

每个博主拥有独立的配置快照、任务、checkpoint、失败状态、恢复游标和摘要版本。某博主的登录失效、权限不足、页面结构变化、处理失败或持久化失败，不得阻断其他博主完成其自身已确认范围。

管理员输入的博主标识表达管理员意图；稳定平台作者身份、当前显示名和 handle 的实际采集与解析规则必须在 V2 Plan 的 X 验证步骤中明确。若运行时无法唯一确认该配置对应的 X 作者，任务必须以可操作的未解析或授权失败状态结束，不能猜测绑定到同名账户。

### 3.2 自然日与成功范围

V2 的读者日历和每日摘要以 `Asia/Shanghai` 自然日为准。一次正常更新或历史补采必须有不可变的起止范围；任务实际开始较晚时，范围上界之后的新帖子留给后续任务，不能静默混入本次摘要。

分页、无限滚动或页面刷新只是网页读取方式，绝不是任务成功条件。每个成功任务必须证明已抵达其时间范围的下界，或以经验证的空结果证明可见历史已耗尽。仅成功读取固定数量卡片、网络请求或屏幕高度，不能被标为完整范围成功。

checkpoint 只能在本范围内原始事实、Canonical 帖子、结构化结果、每日摘要版本和必要证据关系均已成功持久化并获控制面确认后推进。恢复必须从最后安全 checkpoint 或恢复游标继续；任何失败都不得跳过未确认范围，亦不得把失败显示为“无新增”。

### 3.3 四类帖子与观点归因

V2 必须以帖子类型为第一等事实，且以如下语义处理：

| 类型 | 必须保留的事实与关系 | 对博主观点的解释规则 |
| --- | --- | --- |
| 原创 | 帖子本身、作者、时间、链接、附件/外链元数据 | 可作为该博主观点的候选证据，但仍须区分事实、观点和不确定性。 |
| 引用 | 博主附加评论，以及被引用原帖的作者、身份、时间、链接和可见摘要性元数据 | 博主评论与被引用原帖分别保存；只把博主自己的附加评论归为博主观点。 |
| 回复 | 回复内容，以及被回复帖的身份、作者、链接和可见上下文状态 | 回复本身可作为博主观点候选；上下文不可见、删除或无法确认时必须标记，不能补写上下文。 |
| 普通转发 | 转发关系、被转发原帖身份、作者、时间、链接及“无附加评论”事实 | 不得把被转发内容错误写成博主自己的表达、态度或操作建议；可作为原帖入口，但不单独生成博主观点。 |

每条 Canonical 帖子的去重身份必须基于平台可验证的稳定帖子身份与对应作者身份；显示名、handle、文本相同或时间接近都不得单独充当去重键。若帖子类型、关联目标或作者身份无法可靠解析，保留原始事实与解析不确定性，停止在可追溯边界，不生成确定性归因。

### 3.4 内容优先的每日阅读

每位博主、每个自然日只向普通读者默认展示一份当前最新中文摘要。摘要至少包含：

- 当日核心观点或明确的“未形成可归因观点”；
- 涉及的标的、主题或市场条件；
- 明确文本支持的操作倾向、态度变化或“未观察到可验证变化”；
- 事实、博主观点、系统归纳与不确定性的清晰区分；
- 未解析媒体、外部正文缺失、引用/回复上下文缺失和证据不足的提示。

同一自然日的后续成功任务可产生新的摘要版本，并将其设为当前版本；先前版本必须保留且在读者页默认折叠。没有新增帖子时，只能在该博主已完成范围内显示“无新增”，不得凭空生成新摘要版本或覆盖已有版本。

普通读者的原帖入口默认折叠，只显示帖子类型、发布时间和“在 X 中打开”的原始链接。阅读页不展示原始帖子正文、内部身份、原始数据引用、任务诊断、Worker、Prompt、凭据或本地文件路径；后台仍须保留必要的证据关系，以满足保留期内的可追溯性。

## 4. 信息架构与权限边界

### 4.1 阅读体验

阅读页按“自然日 → 博主 → 当前摘要 → 原帖入口 → 历史版本”组织，而不是按 X 混合时间线组织。

- 桌面端提供博主范围选择与日期内容区；主区先选择自然日，再以博主卡片呈现当前摘要。
- 手机端提供顶部日期与博主选择器，并使用单列博主卡片；375px 宽度必须保持选择、摘要、状态和折叠入口可操作且无横向溢出。
- 当前摘要默认展开；原帖入口和历史版本默认折叠。
- 页面必须明确区分 `处理中`、`部分失败`、`可重试失败`、`失败`、`无新增` 与 `成功`。`无新增` 只适用于已验证完整范围内确实没有新帖子；其他失败状态绝不能降级成空内容。

### 4.2 管理与普通阅读隔离

管理员可配置博主、启停来源、初始化或查看其安全覆盖边界、发起手动更新及有界历史补采，并读取任务状态、脱敏错误和局部重试入口。普通用户只可读取共享的安全 X 摘要投影。

上述隔离必须同时存在于页面路由、服务端接口和数据访问策略中。普通用户不能查看或调用博主配置、任务、checkpoint、恢复游标、授权状态、浏览器会话、Provider 运行信息、Prompt、凭据或本地引用；管理员页面也不得展示真实 Cookie、Profile、私有 Prompt、完整模型响应或原始本地路径。

## 5. 采集与处理边界

### 5.1 V2 X 采集验证门槛

X 网页的稳定读取路径尚无项目证据，因此不得将 Discord 的 Active Adapter 或其具体分页实现直接声明为 X 的既有能力。独立 V2 Plan 的第一个实施阶段必须在不改共享协议的前提下，验证一个受限的 X 网页采集候选路径，并产生脱敏的 Go/No-Go evidence。

该验证至少必须证明：

1. 仅使用用户本人已登录、正常可见的 X 网页会话，且登录态不离开 owner-only 本地环境；
2. 能对一个明确配置的博主读取较新的可见帖子，并在连续加载更早内容时可靠识别时间下界或已验证空结果；
3. 能在刷新、重复读取和中断恢复后保持稳定帖子身份去重，不把同一帖子重复持久化；
4. 能区分第 3.3 节四类帖子，并保留引用/回复/转发关系的最小事实；
5. 页面变动、登录/权限缺失、缺失或陈旧响应和上下文不可见会形成分类失败，而不是成功或无新增；
6. 真实验收只记录脱敏计数、状态、类别覆盖和受保护 evidence 位置，不将正文、账户、URL、Cookie、Profile 或完整响应写入 Git。

若该验证不能满足上述条件，实施必须停止在失败结论，保留事实与 evidence，并为替代路径另写增量 Spec/Plan；不得临时切换到直接 API、普通用户 Token 自动化或第二套完整采集框架。

### 5.2 处理、摘要与 Provider

成功范围内的帖子必须先完成原始事实持久化、Canonical 规范化和去重，再进入结构化理解和每日摘要。结构化输出必须引用本次已验证 Canonical 帖子集合；摘要不得引用范围外、未确认、普通转发的被转发正文，或未解析媒体/外部文章正文来形成确定性判断。

当前唯一真实 Provider 候选为本机已登录的 Codex CLI；Mock Provider 只用于确定性测试。Provider 超时、Schema 无法验证或持久化失败必须保留分类失败、局部重试和手动恢复入口，不自动切换 Provider。GLM 与自动 fallback 是历史方案，不属于 V2。

原始 X 内容按项目保留策略保留一年；摘要及摘要版本长期保留。保留期内，受权限控制的证据关系必须能把摘要追溯到帖子身份和原始链接。原始内容过期后，摘要仍可阅读，但相关入口必须准确标记为不可用或已过期，不能伪造原文仍可访问。

## 6. 数据与兼容性原则

V2 需要表达博主配置、任务范围、checkpoint、恢复状态、原始帖子、Canonical 帖子、帖子类型和上下文关系、附件/外链元数据、结构化结果、每日摘要版本及证据关系。这是所需的领域事实，**不是本 Spec 对任何既有共享表、RPC、Worker 协议或阅读 DTO 的修改授权**。

V2 implementation plan 必须在批准后逐项提出最小迁移、读写边界、RLS、回滚顺序和兼容性证明；在该 Plan 批准前，不得更改 Discord/X 共享协议或既有 V1/V1.1 行为。X 的逻辑来源、任务和阅读投影必须能够与 Discord 事实隔离，即使将来 V3 在视觉或导航上统一，也不能混淆来源、作者、帖子类型、checkpoint 或摘要证据。

所有任务事件和摘要版本应保留追加式历史；不得通过覆盖旧版本抹去失败、重试、范围或观点变化。任务范围、配置快照、Provider/Prompt 版本标识和输入 Canonical 集合必须能支持事后解释，但不得把敏感配置或正文暴露给普通读者。

## 7. V2 验收标准与退出门槛

以下项目必须由 V2 Plan 的公开 fixture、跨层确定性测试和经用户明确授权的真实验收共同覆盖；真实验收范围、博主数量和浏览器会话必须在执行前再次获得授权。

### 7.1 采集、身份与恢复

1. 对至少两位独立配置博主，系统能在授权网页会话中完成独立任务；任一博主的登录、页面、Provider 或持久化失败不阻断另一博主的完成。
2. 原创、引用、回复和普通转发的分类与关系均被正确保存；无附加评论的普通转发不被写成博主观点、态度或操作倾向。
3. 每条已接受 Canonical 帖子可追溯到稳定帖子身份、实际作者、发布时间、帖子类型、原始链接和附件/外链元数据；无法确认的上下文以不确定性标记保留，不臆测。
4. 重复读取同一范围、刷新页面和中断恢复不产生重复 Canonical 帖子；相同身份但内容冲突时安全失败并保留审计事件，不覆盖既有事实。
5. 成功任务只在抵达其时间下界或验证历史耗尽后推进该博主 checkpoint；固定页数、卡片数或滚动次数不能作为成功替代条件。
6. 离线或失败后恢复会补齐同一未确认范围；失败的博主 checkpoint 不前移，其他博主可继续运行。

### 7.2 摘要与阅读

7. 每位博主、每个已完成自然日的当前摘要均包含第 3.4 节规定的内容边界；所有可归因结论均能回溯至已验证的输入帖子集合。
8. 引用帖的博主评论、被引用原帖，回复和其上下文，及普通转发的无评论事实在摘要和原帖入口中均不被混淆。
9. 同日后续成功任务会创建可追溯的新版本并更新当前版本；历史版本默认折叠，且不会丢失先前版本的范围与证据关系。
10. 图片、视频、PDF 和外部文章正文均不被解析或臆测；核心判断依赖它们时，摘要明确提示信息不完整。
11. 桌面与 375px 宽度均可完成日期、博主、当前摘要、折叠原帖入口和历史版本的阅读流程；默认读者 HTML/API 不包含原始正文、内部 ID、本地引用、Worker、Prompt、Provider 诊断或凭据。
12. 读者状态正确区分处理中、部分失败、可重试失败、失败、无新增与成功；失败绝不呈现为无内容或无新增。

### 7.3 权限、安全与工程证据

13. 普通用户不能通过页面、接口或数据访问策略读取或操作博主配置、手动更新、历史补采、任务、checkpoint、浏览器会话或运行诊断；管理员仍不能读取或输出受保护的凭据和本地私有内容。
14. 真实验收及工程日志不包含真实帖子正文、账户、URL、Cookie、Profile、私有 Prompt、完整模型响应或本地 evidence；公开 fixture 均为人工构造。
15. 所有确定性、权限、Worker、阅读和跨层测试通过；发布前完成项目脱敏检查与 `git diff --check`。任何权限绕过、checkpoint 越界、事实丢失、重复写入、错误作者归因、媒体臆测或敏感信息泄露均为阻断失败。
16. V2 Final Report 必须逐项记录通过、条件通过或失败，并说明真实 X 验证的边界、未验证的稳定性限制、可恢复失败及后续门禁。只有第 1–15 项全部通过，才能称为“V2 X 正式可用”。

## 8. 实施顺序、回滚与不触碰项

在独立 V2 Plan 获批准后，实施必须遵循以下依赖关系：

```text
受限 X 网页采集验证与分类事实
  └── 博主配置、范围、checkpoint 与恢复语义
        ├── Canonical 帖子/上下文/证据边界
        │     └── 每博主每日摘要版本
        └── 管理员操作与安全阅读投影
所有能力 ──> 公开 fixture、权限/恢复测试、真实授权验收、部署与工程证据
```

先证明读取边界和帖子身份，才能安全保存 checkpoint；先建立类型与上下文事实，才能归因观点；先完成安全数据投影，才能将内容交给普通读者。

回滚时，未完成的 V2 任务必须停止且保持原 checkpoint；新产生但尚未确认的摘要不得成为当前版本。已确认的 V2 摘要版本、任务事件和证据关系应以追加式历史保留，并将当前指针切回上一个有效版本。回滚不能删除或重新解释 Discord 的 V1/V1.1 原始事实、覆盖水位、任务历史或阅读行为。

## 10. Spec 自检

- 问题本质：聚焦指定博主的可追溯每日理解，而非复制混合 X 时间线。
- 事实与归因：四类帖子分别建模；普通转发、引用和回复上下文均不允许错误归因。
- 完整性：每博主独立范围，页数或滚动次数不是成功条件；checkpoint 只在完整持久化后推进。
- 产品边界：每博主每日摘要、原帖链接和历史版本清晰；不做跨博主统一结论或 V3 统一体验。
- 安全边界：真实内容与浏览器会话留在 owner-only 环境；普通阅读与管理/运行信息隔离。
- 阶段边界：本文是待审阅 Draft，不授权代码、共享协议改动、部署或真实 X 采集；V2 Plan 必须独立批准。
