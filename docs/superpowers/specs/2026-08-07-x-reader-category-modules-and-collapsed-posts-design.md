# X Reader 观点分类模块与原始帖子折叠设计

## 文档状态

- 阶段：X Reader 阅读展示可用性改进
- 状态：**已批准（用户确认 2026-08-07）**
- 日期：2026-08-07
- 关联：[X 判断对象范围与阅读展示设计](2026-08-05-x-judgement-scope-and-reader-presentation-design.md)、[X 跨博主当日判断总结 Spec](2026-07-31-x-cross-blogger-daily-judgement-summary-design.md)

## 1. 问题与目标

当前 `/x` 已按“日期 → 当日判断总结 → 单个博主观点”组织内容，但三类观点标题使用普通的较小字号，读者难以快速区分“个股与产业”“市场结构”“投资策略与心态”。同时，单个博主窗口中的每条原始 X 帖子分析默认全部展开，使证据细节在观点正文之前占据过多空间。

本设计只调整 Reader 的视觉组织和默认展开状态：让三类观点成为清晰、连续、可辨识的分类模块，并让原始帖子证据默认折叠。观点内容、证据关系、采集窗口顺序、筛选语义和安全边界均保持不变。

## 2. 已确认方案

### 2.1 分类模块的适用范围

同一套分类模块视觉格式同时应用于两个区域：

1. “当日判断总结”中的“个股与产业判断”“市场结构判断”“投资策略与心态”；
2. “单个博主观点”中的“个股与产业观点”“市场结构观点”“投资策略与心态”。

两处保留“判断”和“观点”的语义差异。前者是跨博主归纳，后者是单个博主表达；视觉对齐不代表内容来源或确定性被合并。

只有实际有内容的分类才渲染分类模块。没有观点的分类继续隐藏，不渲染空模块或占位标题。

### 2.2 分类模块的视觉层级

三类模块纵向排列，不在桌面端并排成三列。原因是观点正文可能较长，纵向结构能保持连续阅读顺序，也能让桌面端与 375px 移动端保持同一信息顺序。

每个模块包含：

- 显著的分类标题栏，目标字号约为 `1.15rem–1.35rem`，明显高于当前普通 `h3`；
- 低饱和的分类背景色；
- 细边框和该类别的强调色；
- 模块内部继续使用观点编号、左侧强调线和观点之间的细分隔线；
- 不给每条观点增加完整独立外框，避免出现“分类模块套观点卡片套字段卡片”的层层嵌套。

分类使用克制的语义色：

| 分类 | 强调色方向 | 背景色方向 |
| --- | --- | --- |
| 个股与产业 | 蓝绿色 | 极浅蓝绿色 |
| 市场结构 | 暖金色 | 极浅暖黄色 |
| 投资策略与心态 | 低饱和紫灰色 | 极浅紫灰色 |

颜色只用于建立类别识别，不表达“看多/看空”、风险等级或操作建议。正文、支持/不同观点、条件和不确定性继续使用现有的语义颜色规则。

### 2.3 默认展开状态

展开边界固定如下：

| 内容层 | 默认状态 | 说明 |
| --- | --- | --- |
| 最新博主窗口 | 展开 | 保持现有最新窗口优先的阅读规则 |
| 历史博主窗口 | 折叠 | 保留历史追溯能力 |
| 有内容的观点分类模块 | 展开 | 观点正文属于主要阅读内容 |
| 原始 X 帖子证据 | 折叠 | 证据细节按需展开 |
| 跨博主判断历史修订 | 折叠 | 保持现有修订历史规则 |

原始帖子折叠后仍显示“原始 X 帖子”入口和展开指示符，并保留现有帖子链接。展开后继续显示当前已有的博主观点、操作表述、条件、论据、引用帖观点和不确定性；不新生成摘要，不删除或重写现有字段。

## 3. 信息结构示意

```text
日期
├── 当日判断总结
│   ├── 个股与产业判断模块（展开）
│   │   ├── 观点 01
│   │   └── 观点 02
│   ├── 市场结构判断模块（展开）
│   └── 投资策略与心态模块（展开）
└── 单个博主观点
    └── 博主 A
        ├── 最新窗口（展开）
        │   ├── 个股与产业观点模块（展开）
        │   ├── 市场结构观点模块（展开）
        │   └── 原始 X 帖子 ▸（折叠）
        └── 历史窗口（折叠）
```

## 4. 范围与非目标

本次范围仅包括：

- X Reader 跨博主判断和单个博主观点的分类模块视觉层级；
- 原始 X 帖子分析的默认折叠状态；
- 桌面端与 375px 移动端的布局、间距、可读性和键盘操作适配；
- 对应的 Reader 组件测试和展示回归测试。

本次不改变：

- 数据库、Reader API、Reader-safe DTO、Prompt、Schema、LLM Provider 或 Worker；
- 观点文字、支持/不同观点、条件、不确定性和操作表述的语义；
- 日期/博主筛选、URL 语义、博主分块、最新窗口优先和历史保留；
- 原始帖子证据的保存、链接、权限和安全脱敏边界；
- 任何采集、任务、checkpoint、coverage、部署或生产数据。

## 5. 验收标准

1. 当日判断总结和单个博主观点中的三类非空内容都使用统一的分类模块结构；“判断”和“观点”文字仍按各自语义保留。
2. 分类标题明显大于当前普通 `h3`，并通过标题栏、浅色背景、边框和类别强调色形成清晰模块区隔。
3. 三类模块纵向排列；每条观点保留现有观点编号、正文、条件、支持/不同观点和不确定性展示，不出现多层完整卡片嵌套。
4. 最新博主窗口仍默认展开，历史窗口仍默认折叠；有内容的分类模块默认展开，空分类不渲染。
5. 每条原始 X 帖子默认折叠，折叠状态下仍可看到并打开“原始 X 帖子”入口；展开后现有分析字段完整可读。
6. 跨博主判断的最新批次、历史修订、单博主窗口的顺序与当前行为一致，分类样式不得改变其语义或顺序。
7. 桌面端和 375px 宽度下，标题、长观点、链接和不确定性无横向溢出；分类模块的颜色对比和键盘焦点状态可读。
8. 普通 Reader 页面继续只输出 reader-safe 内容，不新增内部 ID、Prompt、Provider、运行诊断、原始正文或本地路径。
9. 公开 fixture、Reader 组件测试、展示回归、lint、production build、`git diff --check` 和脱敏检查通过后，才具备进入独立 implementation plan 的验证基础。

## 6. 后续门禁

本 Spec 已获用户批准。下一步使用独立 implementation plan 明确组件/CSS 改动边界、测试案例、375px 验收方式、回滚范围和部署后的登录态 Reader 验收步骤；Plan 执行期间仍不得修改数据、API、Prompt、Worker 或采集边界。
