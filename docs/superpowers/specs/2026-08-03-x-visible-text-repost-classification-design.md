# X 可见正文与 repost 关系修正设计

## 文档状态

- 阶段：V2 / X 采集语义修正
- 书面状态：**已批准（用户明确授权 2026-08-03 自行按流程以最小范围实施）**
- 事实输入：用户给出的 X 帖子 `2084067672032166381`、生产只读记录、[V2 X Spec](2026-07-22-v2-x-information-collection-and-reader-design.md)、[本地 Collection 采用 Plan](../plans/2026-07-24-v2-local-opencli-collection-adoption.md)
- 问题：当前 Adapter 将任何 `relationship.kind = repost` 的 `text` 强制改为空，Canonicalizer 也拒绝 `repost + 非空 text`；Prompt 因而把有可见博主正文的帖子当作“未表达”。生产记录已证明该帖子在进入持久化前正文已丢失。

## 1. 目标与范围

目标是只修正“可见博主正文被 repost 标签掩盖”的归因错误：在已验证的 Collection 行中，正文是非空字符串时，保留该行原样提供的正文并允许其参与逐帖和窗口观点分析。`repost` 关系及其目标身份仍保存；目标帖或缺失上下文绝不能被当作博主正文。

本变更不新增采集器、表、Reader 页面或 Provider，不改变范围回执、checkpoint、普通无正文 repost 的处理，也不解析媒体、外链或不可见上下文。

## 2. 事实模型与判定

`relationship.kind` 与“本卡片是否有可归因的博主可见文字”是两个独立事实。最小模型仍使用既有 `post_type = repost` 和 `reposted_post_id` 保存关系；`text` 的非空性表达已由 Collection 返回、且尚未被项目加工的可见正文。

| 输入关系与正文 | 保存与分析 |
| --- | --- |
| `repost` 且正文为空 | 保留转帖关系；不得生成博主观点。 |
| `repost` 且正文非空 | 保留转帖关系和原样正文；正文可作为博主观点候选，模型仍须只依据该正文作判断。 |
| `quote`、`reply`、`original` | 维持既有处理。 |

Adapter 只能传递 Collection 行的 `text`，不得从关系目标、`quoted_tweet`、媒体或上下文补写文本。Canonicalizer 只验证“该输入已有可见文本可以共存”，不生成文本。Prompt 明确以“`post_type` 为 `repost` **且 text 为空**”作为不得生成博主观点的条件。

## 3. 历史受影响记录

未来采集经上述修正后会保留正文。已写入生产的错误记录不能由例行任务静默覆盖：项目的 X 事实为追加/不可变设计，且原本的本地证据同样已被清空。

本次只处理用户指出的单帖。代码与自动化验证通过后，使用已登录网页会话重新读取该稳定帖子；只有读取结果的 `id`、作者、链接与生产记录一致，且正文非空时，才执行一次受审计的、单行事实勘误和重新分析。勘误输入不得写入 Git；读取不一致、页面不可用、模型/Schema/持久化任一失败时停止，不修改生产数据，也不把旧页面表述为已修复。

## 4. 验收与回滚

确定性测试必须证明：非空 repost 正文不被 Adapter 删除、Canonicalizer 保留它、空 repost 仍无正文；Prompt 的约束不会否定前者。既有 Collection receipt、关系 ID、无上下文标记和所有其他帖子类型回归必须通过。

真实验收只验证该单帖的稳定身份、可见正文保留、结构化分析和 `/x` 投影；不输出或提交真实正文。若需回滚代码，恢复到本修复前提交即可；生产勘误仅在成功验收后执行，保留前后 payload hash、时间和操作者的脱敏审计信息。

## 5. Spec 自检

- 范围仅限 repost 与可见正文的错误归因。
- 关系事实与博主正文分离，不把被转帖内容写成博主观点。
- 无正文 repost、范围/回执、数据权限和 Reader 投影保持不变。
- 历史单帖修复须重新读取和逐项验证，不使用截图或模型记忆补写事实。
