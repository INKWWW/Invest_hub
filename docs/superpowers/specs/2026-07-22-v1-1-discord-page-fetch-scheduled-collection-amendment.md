## 文档状态

- 状态：**已批准（用户确认 2026-07-22）；实现、确定性验证与真实授权验收按配套 Plan 依序执行。**
- 日期：2026-07-22
- 修订对象：[V1.1 Discord 完整时间窗采集与观点阅读 Spec](2026-07-22-v1.1-discord-windowed-collection-and-insight-design.md)
- 修订原因：当前 Browser Bridge 无法可靠驱动 Discord 的嵌套虚拟消息列表，不能触发历史页；Page Fetch 将替代这一传输步骤，并且必须接受现有定时任务的完整时间窗契约。

## 1. 修订后的产品决定

Page Fetch 不是一次性手动 Probe，也不是新的独立 cron。它是 V1.1 既有 Discord 采集任务的读取传输方式：本地 owner-only Worker 在每个已到期的上海时区窗口领取任务后，在已登录的 Discord 网页会话中按任务的 `end_at`、`resume_cursor` 和 `start_at` 增量读取消息页。

调度时刻、任务顺序、补窗、管理员“更新至当前时间”、普通用户权限和 Reader 输出保持不变：

| 触发时刻 | 正常范围 |
| --- | --- |
| 00:00 | 前日 20:50 ～ 当日 00:00 |
| 08:00 | 当日 00:00 ～ 当日 08:00 |
| 16:00 | 当日 08:00 ～ 当日 16:00 |
| 20:50 | 当日 16:00 ～ 当日 20:50 |

## 2. Page Fetch 采集契约

1. 任务由既有控制面创建不可变 `(start_at, end_at]`；Page Fetch 不得自行决定范围，也不得读取 `end_at` 之后的消息。
2. Worker 只在既有、已登录、owner-only Chrome Profile 的页面上下文执行读取；不得导出、持久化或输出 Token、Cookie、Authorization、请求头或浏览器 Profile。
3. 每次读取必须验证目标频道、响应新鲜度、消息 ID 去重、页时间上下界和 cursor 单调性。每个已验证页均沿用现有 raw/Canonical、capture segment、resume 和 lease 机制。
4. Page Fetch 必须持续读取直至最旧已验证消息早于或等于 `start_at`，或有已验证的历史耗尽证据；页数、消息数量、执行时长或请求预算绝不能标记任务完成。
5. 正常运行时，同一来源串行读取；无 backlog 时只读取自上一 coverage 水位以来的增量。离线积压仍按既有任务顺序恢复，不做全历史扫描。
6. 401、403、429、验证/挑战页面、频道不匹配、响应模式变更、cursor 不前进、持久化失败或 Schema 错误，均使任务安全失败或延后恢复。不得推进 `coverage_through_at`，不得伪造空窗口、自动改用其他读取方式或绕过服务端限制。

## 3. 明确边界

- 本修订只替换 Discord 消息页读取的传输方式；不新增来源、云端浏览器、第二套采集框架、普通用户 Token、Bot Token、代理、伪装请求、随机化规避检测或新的 Provider。
- 运行时间继续由固定四个窗口和管理员手动更新决定；不采用“正负十分钟随机启动”来规避检测。
- 不限制 `max_pages`。单页重试与服务端指示的等待仅是失败恢复机制，不能成为完成条件。
- 真实来源、请求参数、游标、消息正文、认证材料和真实证据只可存在于受保护的本地运行时/证据目录，绝不进入 Git、公开 fixture、产品 Reader 或工程文档。

## 4. 上线前验收

### 4.1 确定性验收

公开人工 fixture 必须证明：

1. 从最新页向 `start_at` 连续读取，跨 7、25、100+ 页仍不因数量停止；
2. `end_at` 后消息不会进入范围；
3. 中断后从已持久化 `resume_cursor` 恢复，且不重复、不漏采；
4. 401/403/429/挑战页/频道错配/cursor 不前进不会推进 coverage；
5. 调度仍准确创建四个窗口、补齐离线窗口，并由 Page Fetch 消费任务；
6. 日志、接口、Reader 和 fixture 不泄漏原文、认证材料、内部来源身份或 cursor。

### 4.2 真实授权验收

先对管理员确认的一个既有来源完成一个正常定时窗口和一次手动更新，再在用户明确确认后扩展到第二来源。每次真实验收只记录安全结果：任务范围是否完整、页数/消息数统计、边界是否证明、是否发生受控停止，以及 coverage 是否正确前移；不记录真实正文或来源身份。

通过一次真实窗口只证明该窗口的技术行为，不承诺长期无人值守 SLA。任何验证、拒绝或限流信号均暂停后续自动运行，等待用户决定。

## 5. 对原 V1.1 Spec 的替换关系

本修订经批准后，替换原 Spec 第 3.2 节中“直接 Discord REST API”的绝对非目标，仅在本修订定义的已登录网页页面上下文、owner-only、无凭据导出、受控失败语义内允许 Page Fetch。原 Spec 的时间窗、RLS、证据、媒体、作者、阅读安全和无 `max_pages` 条款全部继续有效。
