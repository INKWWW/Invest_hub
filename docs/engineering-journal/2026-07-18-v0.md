## 重要修复

1. Supabase 邀请消费现在区分 `user` 和 `worker` 用途；Worker ID 不再被强制关联到认证用户外键。
2. Provider 超时清理会关闭 stdin，终止整个进程组，并且只在有界的清理窗口内等待。
3. 结构化输出会拒绝未知、非媒体或缺失的 `media_source_message_ids`；该集合必须与当前分块中未解析媒体的 ID 完全一致。
4. Next.js 构建最初无法识别 TypeScript 7 的包布局。现在控制面固定使用 TypeScript 5.9.3 及匹配的解析器，`npm ci` 可以复现该环境。
5. 端到端 shell 入口会拒绝低于 3.11 的 Python，而不是输出容易误导的 Worker 导入回溯信息。

```text
cd apps/control-plane && npm ci
cd apps/control-plane && npm run lint && npm test && npm run build
PYTHONPATH=workers/v0/src python3.11 -m unittest discover -s workers/v0/tests -p 'test_*.py' -v
PYTHONPATH=spikes/spike_01:spikes/spike_02 python3.11 -m unittest discover -s spikes -p 'test_*.py' -v
V0_PYTHON_BIN=python3.11 bash scripts/v0/run-e2e.sh --mode deterministic --provider mock --chunk-size 100 --max-concurrency 5 --timeout-seconds 240 --max-attempts 3
supabase test db
bash scripts/v0/redact-check.sh
```

实际本机使用的 Python 3.12 运行时与上述 `python3.11` 命令等价；系统 Python 3.9 不满足 Worker 要求。
