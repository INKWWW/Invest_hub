# V1 Engineering Journal: Discord 正式可用 MVP

日期：2026-07-19（2026-07-20 更新）
阶段：V1 已部署；真实双来源有界 history 路径通过；正式可用 MVP 的剩余验收待执行

## 目标与边界

本阶段只实现 Discord 多来源阅读 MVP。浏览器 Profile、Cookie、真实 Discord URL、私有 Prompt、完整模型响应和本地 evidence 均不进入仓库、控制面 payload 或普通用户页面。

## 已实现的闭环

- 为来源授权、规则快照、有界增量/历史任务、批次摘要、日累计摘要和摘要收据增加数据库原子边界；checkpoint 只能在 receipt 与摘要 ID 匹配后推进。
- Worker 支持 owner-only 多来源配置、规则归因、最多 5 页的常规同步、显式 1–25 页历史任务和 Active Adapter freshness 失败分类。
- 管理员可以管理来源启停/Worker 绑定、作者规则和有界补采；普通用户可在 `/discord` 阅读共享的安全 DTO。
- 阅读页提供频道和日期选择、当前日累计摘要、批次展开、原始消息证据、摘要历史、处理中/失败状态与证据过期标记；不会输出 local raw ref、任务诊断、Worker、凭据、Prompt 或 Provider secret。
- 定时窗口固定为 Asia/Shanghai 的 08:00 与 20:50。数据库以 `(source_id, window_key)` 唯一键保证跨重启、跨进程重复 tick 返回同一任务；本地 Worker 至多补最近 48 小时的四个窗口，超出范围只记录脱敏 warning 并等待管理员创建有界历史任务。

## 2026-07-20 真实双来源增量、二次去重与 checkpoint 验收

- 本机受保护 Worker 配置继续只含已有两个授权逻辑来源；配置与频道的配对按用户确认的创建/打开顺序完成，未向仓库写入来源标识、URL、正文或 Prompt。替换 Worker 的一次性注册凭据、Vercel 自动化绕过密钥、配置、原始响应和 evidence 均只存在于 owner-only 本机目录。
- 两轮各为两个 `incremental`、`max_pages=1` 任务；共 `4` 个任务均为 `succeeded`，且均只使用 `1` 次 attempt。第一轮覆盖两个来源，新增 `30` 条 Canonical，Worker 报告重复为 `0`，两个 checkpoint 均在成功后前移。
- 第二轮以相同范围再次覆盖两个来源，新增 `19` 条 Canonical；Worker 报告重复仍为 `0`，数据库按 `(source_id, external_message_id)` 聚合的重复 Canonical 行数为 `0`，两个 checkpoint 再次只在成功后前移。第二轮新增数据未出现重复持久化。
- 完成后只读聚合为 `6` 次 structured run、`21` 个 batch、`21` 个日摘要版本（其中 `18` 个为当前版本）和 `139` 条 evidence reference。每轮的来源级计数、checkpoint 摘要和终态均已存入本机受保护 evidence；本记录只保留脱敏总数。

## 2026-07-21 可操作失败隔离与恢复验收

- 受控失败前的 A/B 基线、配置备份和来源级计数均保存在仓库外 owner-only evidence。临时移除 A 的本地映射后，A 的第一次 attempt 按预期为 `retryable_failed/unauthorized`，没有新增 raw、Canonical、摘要或 evidence，checkpoint 未前移；过程中未打开 A 频道。
- 完整配置恢复并复核为 owner-only 后，B 在同一 `incremental/max_pages=1` 范围独立成功，新增 `14` 条 Canonical 且 checkpoint 前移；A 的失败没有阻断 B 的领取、持久化或回报。
- A 的正式 Retry 初期反复在持久化边界被安全回报为 retryable failure。阶段诊断证明采集、Canonical、证据和 Codex 结构化均可完成，失败固定发生在远程 `persist`；运行与数据库日志将原因收敛为 `conflicting_raw_message`。
- 受保护的只读对比显示，`10` 条重采集消息中 `9` 条与已存消息重叠，`9` 条 payload hash 均一致，但每次采集的本地 evidence 引用不同。这是可预期的捕获位置变化，不是内容冲突。新增迁移 `20260720165534_v1_allow_stable_raw_recapture` 仅在同 ID、同 hash 时复用既有 raw evidence 引用；hash 与 Canonical 内容冲突仍拒绝持久化。迁移已应用至专用 V1 Supabase，且远程 migration history 已复核。
- 新增 pgTAP 回归覆盖“同 payload、不同本地 evidence 引用”的重采集；本地完整结果为 `6` 个 pgTAP 文件、`115` 条断言和 `62` 个 Worker 测试全部通过。恢复后的管理员正式 Retry 在第 `7` 次 attempt 成功：前 `6` 次 retry 事件与最终 succeeded 事件均保留，checkpoint 在成功后更新；来源 A 仅新增 `1` 条 raw/Canonical，并生成 `1` 个 structured run、`8` 个 summary batch 与 `20` 条 evidence reference。所有逐任务计数保存在 owner-only evidence。

## 结论

V1 的代码、迁移、确定性验收、阅读体验发布、隔离部署、真实双来源有界 history、真实增量/二次去重/checkpoint，以及可操作失败隔离与恢复验收已完成；它仍不能称为“Discord 正式可用 MVP”。达成该称谓前，必须补齐普通用户正式阅读和基于真实内容的桌面/手机视觉验收，并完成一次基于真实运行的人工质量抽检和部署日志独立审阅。
