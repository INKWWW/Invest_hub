# V1.1 Discord 采集方案探索与收口决定

日期：2026-07-22  
状态：**已收口；个人账号采集不进入生产。**

## 用户决定

Discord 部分先停在当前状态。项目已在当前边界内探索多种采集方向，但生产环境使用个人 Discord 账号自动化存在账号与合规风险；后续考虑引入由频道管理员授权的 Bot 方案。

这是一项范围决定，不是某一条技术路线的失败重试指令。自本记录起，Discord 不再阻塞其他模块的规划与开发。

## 已探索的方向与结论

- Browser Bridge 驱动页面历史列表：无法稳定证明对嵌套虚拟列表的历史翻页控制，未作为持续采集能力上线。
- 页面上下文 Page Fetch：仅做受控兼容性探索；未通过生产接入验收，相关探索代码未合并、未部署。
- 个人账号直接接口、导出器或其他自动化：不作为生产方案，避免导出认证材料、自动化个人账号或扩大账号风险。
- Discord 用户数据包：不满足频道研究所需的完整他人消息历史范围，不能替代频道采集。
- 频道 Bot：保留为未来候选方向；前提是频道管理员同意邀请并授权 Bot。

上述结论只覆盖本项目已评估的路线与当前权限边界，不声称已经穷尽 Discord 的所有可能集成方式。

## 当前运行状态

- 既有 V1 Discord 阅读页与已持久化数据保持可用；它们不代表新的持续采集能力。
- 不启用 Discord Page Fetch 定时任务、管理员手动采集、launchd 安装、真实窗口验收或 coverage 前移。
- 未合并的 Page Fetch 探索实现不得合并、部署、推送或宣称为已验收功能。
- 不继续重复个人账号页面采集尝试，也不记录、导出或使用个人账号认证材料。

## 未来重新启动的前提

用户完成与频道管理员的沟通并取得 Bot 授权后，才可新建 Discord Bot 采集的 Spec 和 implementation plan。该未来范围应明确：

- 每个频道的最小读取权限与管理员授权记录；
- 是否仅允许管理员手动触发；
- 消息内容访问所需的应用授权条件；
- 增量 checkpoint、失败不前移、审计记录与证据边界；
- Bot 凭据的 owner-only 保存与绝不进入 Git 的约束。

在新的 Spec/Plan 获批前，不实现、不部署、不尝试 Bot 采集。
