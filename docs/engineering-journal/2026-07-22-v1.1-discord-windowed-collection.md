## 目标与边界

V1.1 将 V1 的“按页数抓取”改为“可证明完整的时间窗抓取”：每个来源按上海时间 00:00、08:00、16:00、20:50 建立不可变的 `(start_at, end_at]` 范围。任务只有在持久化范围内事实、摘要和证据，并已验证到达下界后，才能推进来源的 `coverage_through_at`。

本阶段同样增加频道级稳定作者配置、日内作者观点卡、署名话题观点，以及管理员“更新至当前时间”。普通读者只得到安全的内容投影，不得到原始正文、来源 ID、游标、Worker/Provider/Prompt 或本地引用。

本次没有扩大到 X、媒体内容解析、外部文章正文、第二套浏览器采集框架、普通用户手动任务或新的 Provider。

## 关键实施决定

- **页数不是完成条件。** `max_pages` 被拒绝为新的 V1.1 任务语义；分页仅是浏览器读取的传输细节。长历史通过逐页 segment 和 `resume_cursor` 恢复，直到页面时间下界到达 `start_at` 或已验证空页证明历史耗尽。
- **覆盖水位与恢复游标分离。** `coverage_through_at` 只在完整范围回执的来源级事务中前移；`resume_cursor` 只服务于未完成任务，不能将失败区间伪装为已覆盖。
- **时间边界由可信控制面固定。** 定时/手动任务的 `end_at` 创建后不可变；实际运行时较晚的新消息不进入该任务。手动任务复用同来源尚未完成任务，避免并发重叠范围。
- **作者与观点必须可归因。** 管理员只能从已观察到的稳定 Discord ID 配置作者。日累计卡片包含作者、市场/个股核心逻辑、操作倾向、方法论和不确定性；话题观点带作者与受控证据关系。未解析媒体只生成不确定性提示，不推断内容。
- **阅读 DTO fail closed。** 读者页不返回 raw 正文、本地 raw 引用、内部 ID、游标或 Provider 诊断；V1.1 结构不完整或媒体提示不一致时不会投影为可读总结。

### 会话可操作性热修复（2026-07-22）

真实验收进入管理员配置前发现：普通用户访问 `/admin` 会先得到服务端 403、随后被静默导向 `/discord`；同时产品没有登出 API 或页面入口，用户无法切换回管理员账号。根因不在 RLS 或角色判定，而在管理员 layout 将 403 重定向至首页、首页又按普通用户角色重定向至阅读页，以及 UI 未暴露会话终止操作。

用户确认热修复后，`082e5b7` 做了最小修正：保留原有服务端 `requireRole("admin")`；普通用户改到说明边界且可切换账号的 `/forbidden`；阅读页和管理员页右上角显示当前账号与角色，并提供由服务端 Supabase SSR client 执行的“退出 / 切换账号”。接口只返回受控成功/失败状态，不返回认证材料。新增回归覆盖管理员/阅读页账户控件、登出 API、403 目的地和无权限页。验证为控制面 17 个测试文件/76 项、lint、production build、V1.1 E2E、redaction 与 diff 检查通过。

专用 V1 远程数据库 migration 已完成且历史匹配。`082e5b7` 已部署至专用 V1 生产项目；管理员生产页确认保留 `/admin`，账号/角色/切换按钮可见，375px 下控件未溢出。为不打断当前管理员会话，没有在生产点击登出；登出成功路径由自动化接口测试覆盖。

随后真实 Sources 页核验发现覆盖初始化 API 没有表单入口，无法进行首次采集。`54c472d` 新增每来源的“首次采集范围”表单：日期默认留空，管理员必须选择日期与 00:00、08:00、16:00、20:50 之一的上海边界；初始化成功后仅显示连续覆盖状态，不能从页面更改。生产确认两个来源均出现该控件和四个边界选项。控制面全量验证更新为 18 个测试文件/77 项通过；V1.1 E2E、lint、build、redaction 与 diff 检查继续通过。
