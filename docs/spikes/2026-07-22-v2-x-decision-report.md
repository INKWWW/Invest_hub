# V2 Final Report：X 指定博主信息收集与阅读

日期：2026-07-24

结论：**Conditional — V2 X 已进入受控生产试运行，尚不能标记为“V2 X 正式可用”。**

## 判定原则

V2 的核心不是把 X 页面搬运到阅读页，而是让每位已配置博主的事实、理解、每日观点和连续覆盖水位保持可追溯。一次真实任务成功不等于持续运行可靠；普通用户真实阅读验收必须与管理员或公开 fixture 验证分开记录。

## 已验证交付物

- 生产控制面已部署；其数据库绑定已与 X Worker 实际成功领取并完成任务的数据库一致。
- 一次真实、已持久化的 X 范围闭环成功：范围内原始、Canonical 与逐帖分析各 `8` 条，并生成 `1` 个每日观点段；不在仓库或报告中记录博主、帖子、链接或模型正文。
- `com.investhub.x-worker` 已作为 X 专用本机 `launchd` 服务安装并处于运行状态。它只接受 owner-only 的纯 X 配置、受控 OpenCLI 可执行文件与 `V2_REAL_X_ACK`，不会加载或启动 Discord 采集。
- 服务每分钟请求一次安全的调度 tick；控制面只在上海时间 `08:00 / 12:00 / 16:00 / 20:00 / 次日 00:00` 到期或发现未完成范围时创建任务。服务恢复后以最后成功 checkpoint 补齐，而不把缺口显示为无新增。

## 仍未通过的正式退出门槛

1. 观察至少一个由新常驻服务自动投递并完成的真实 X 窗口；随后在出现可恢复失败时记录一次安全恢复，或明确将该项保留为长期运行观察而非已验证能力。
2. 扩展真实样本，覆盖实际可见的引用、回复与普通转发；无法取得的类别继续保持 conditional，不得用 fixture 替代真实类别结论。

在上述条件补齐前，V2 X 可以作为受控试运行的已登录阅读能力，但不应标记为“V2 X 正式可用”，也不构成无人值守 SLA。上游出现满足相同 `collection + receipt` 合同的官方 OpenCLI 版本时，仍由管理员人工复核后再决定是否切换。
